# GH201 분석 무효화와 재개 안내

관련 이슈: https://github.com/catchhole-soma/catchhole-backend-java/issues/201

## 구현 범위

확정 설정 직접 수정으로 완료 분석까지 무효화되던 경로를 제거하고, 진행·실패 재개가 필요한 분석의 입력을 보호한다. 시작 회차 이후 확정 이력으로 자동 분석이 불가능한 경우와 기존 순차 분석을 재개해야 하는 경우를 응답 코드와 화면에서 구분한다. 기존 무효화 결과에는 원고 목록의 개별 직접 검토 경로를 제공한다.

사용자 취소 API, 실패한 실행을 남겨 둔 채 완료분을 먼저 수정·확정하는 부분 검토, 과거 확정 상태의 자동 복원은 이번 범위에 포함하지 않는다. DB migration, AI 프롬프트, Worker lease/checkpoint 계약은 변경하지 않는다.

## 확정 설정 직접 수정

캐릭터 이름·역할·첫 등장·현재 설정, 캐릭터 보관·복구, 세계관 생성·분류·이름·속성을 변경할 때 작품 잠금을 먼저 획득한다. `AnalysisRunStateService.assertSettingMutationAllowed`는 해당 작품의 순차 분석을 다음 기준으로 확인한다.

| 순차 Job 상태 | 의미 있는 직접 설정 변경 |
|---|---|
| PENDING / RUNNING, journal이 INVALIDATED가 아님 | 409로 거절 |
| FAILED + journal PENDING / INCOMPLETE | 고정 입력 재개를 보호하기 위해 409로 거절 |
| SUCCEEDED + journal INCOMPLETE | 같은 Job의 보완 재개를 보호하기 위해 409로 거절 |
| SUCCEEDED + journal SEALED | 허용, 완료 기록과 당시 입력 보존 |
| INVALIDATED 또는 CANCELED | 이 기록 자체는 직접 설정 변경을 막지 않음 |

`FAILED + SEALED`는 기존 재개 검증이 허용하는 조합이 아니므로 재개 대기 상태로 취급하지 않는다. 별도의 진행·재개 대기 Job이 하나라도 있으면 작품 전체 직접 변경은 계속 제한한다.

실패·불완전 기록은 현재 원문 버전이 일치하고 동일 작품·batch·회차·jobType의 최신 작업일 때만 재개 대기로 취급한다. 원문이 바뀌거나 더 최근의 분석으로 대체된 과거 실패는 설정을 영구 잠그지 않는다. 최신 작업은 `createdAt DESC, id DESC`로 정하며, 같은 시각에 생성된 작업도 동일한 순서로 판단한다. PENDING/RUNNING 보호는 이 예외와 별개로 유지한다.

거절 시 `ANALYSIS_REVIEW_WAIT_REQUIRED`를 반환한다. 문구는 실행 중과 재개 대기를 함께 설명하고 분석 목록으로 안내한다. 직접 편집으로 완료 prefix를 무효화하거나 진행 중 Job의 lease를 제거하지 않는다. 실패 회차 재개는 기존 retry API를 사용한다.

캐릭터·세계관 후보의 편집·연결·확정·제외에도 같은 보호 규칙을 적용한다. 마지막 회차 또는 단일 회차만 실패해 `PENDING/RUNNING` Job이 없어도 재개 가능한 고정 입력이 남아 있으면 사용자 변경을 거절한다. 이미 확정·제외한 요청의 멱등 성공 응답과 자동 반영 진행 중 오류의 우선순위는 유지한다.

### 동일값 저장

- 캐릭터는 정규화된 이름·역할·첫 등장과 현재 설정 전체를 비교한다. 나이·레벨의 숫자 동치, 기존 JSON 속성, legacy scalar 동치는 기존 비교 규칙을 재사용한다. 같은 요청은 새 Fact나 provenance를 만들지 않는다. 편집 대상이 아닌 TIME 항목은 유지한다.
- 세계관 분류·이름은 Entity 정규화 후 version 변경 여부로 판단한다.
- 세계관 속성은 경로·이름·값과 수동 보호 여부를 함께 비교한다. 동일 표시값이어도 아직 보호되지 않은 자동 설정을 수동 보호로 전환하면 의미 있는 변경이므로 진행·재개 대기 중 거절한다. 이미 보호된 동일값 저장은 허용한다.
- 세계관 Entity에서 실제 변경 여부를 판단한 뒤 guard가 거절하는 경우 서비스 트랜잭션 전체를 rollback한다. 거절된 이름·속성·보호 상태가 DB에 남지 않으며 이미지 변경은 guard 통과 후에 수행한다.

## 기존 분석 재개와 중복 생성

분석 생성은 같은 batch·회차·jobType의 최신 Job을 확인한다. 현재 원문 버전이 일치하고 아래 조건의 ordered Job이 남아 있으면 `ANALYSIS_ORDERED_JOB_RETRY_REQUIRED`(409)를 반환한다.

- FAILED이며 journal이 PENDING 또는 INCOMPLETE
- SUCCEEDED이며 journal이 INCOMPLETE

이 확인은 미검토 후보 삭제, 사용량 사전 검사, 새 Job/run 초기화 전에 수행한다. 생성 응답 유실 뒤 같은 요청을 반복하더라도 완료한 추출과 비교를 새 실행으로 덮지 않는다. 요청 모드를 MANUAL로 바꿔도 같은 고정 입력 실패의 복구 검증을 우회하지 않는다.

정상 재개는 같은 Job·run·checkpoint와 완료 prefix를 유지한다. 원문이 바뀌었거나 기존 실행이 INVALIDATED라면 이 중복 생성 guard에 해당하지 않으며, 기존 원문·미래 확정 이력 등 별도 생성 검증을 계속 받는다. 거절된 생성 요청 자체는 새 분석 비용을 발생시키지 않는다.

이미 더 최근 작업으로 대체된 과거 ordered Job의 retry 요청은 `ANALYSIS_JOB_SUPERSEDED`(409)로 거절한다. 직접 설정 수정에서는 오래된 실패를 잠금에서 제외하면서, 사용자가 뒤늦게 그 고정 입력을 재개해 새 설정을 덮는 경로는 열지 않는다. 새 작업과 과거 이력은 변경하지 않는다.

## 원문 변경과 현재값 보호 통일

원문 수정·파일 교체·삭제는 바뀐 Episode ID의 과거 순차 Job과 영향 이후 미완료 순차 입력만 무효화한다. 정상 완료(`SUCCEEDED + SEALED`, AUTOMATIC은 automaticAppliedAt 존재)된 다른 회차의 Job·입력 hash·분석 결과·확정 설정은 보존한다. 같은 묶음과 별도 묶음 모두 같은 규칙이며 다른 작품에는 적용하지 않는다. 번호 이동은 이전/새 번호의 최솟값으로 영향을 찾되, 완료된 변경 당사자는 Episode ID로 식별해 누락하지 않는다.

완료된 후행 기록에도 이전 원문 근거가 복사돼 있을 수 있다. 커밋 후 원문 파기는 복사된 journal·S0·automatic input·comparison context의 원문 근거를 정리하되, 결과를 재분석 필요 상태로 되돌리지 않는다. `sourceEvidencePurged`와 기존 hash를 남겨 해당 자료를 실행 입력으로 replay하지 않는다. 교체한 회차 자신의 미확정 후보는 삭제하고 확정 설정은 보존한다. 미완료 후행 작업의 동일 입력 재개는 계속 거절한다.

개별 직접 검토 재분석 후보도 GH199 현재값 보호를 재사용한다. 같은 대상/항목/범위의 후행·같은 회차 확정값, 직접 수정, 제거 흔적, 출처 불명 값은 현재 상태를 보존하고 이력만 남긴다. 새 항목 또는 확인 가능한 근거가 모두 앞 회차인 항목은 현재값에 반영할 수 있다. 일반 비교의 현재값·버전·의존성·공유 결정·범위 이동 검증을 먼저 유지한다. 캐릭터 병합/제거의 부수 삭제와 세계관 범위 이동의 원본/목적지도 보호한다. 실제로 의존하는 제안이 이력 처리되면 그 제안에 의존한 변경을 현재값으로 단독 실행하지 않는다.

캐릭터·세계관은 공통 `AnalysisCandidateSourceGuard`를 사용해 파기 예약/보관/현재 원문 manifest 불일치를 확정 전에 거절한다. 생성시 manifest 없는 legacy는 추측으로 유효하다고 복원하지 않고 기존 보관·파기 검증을 유지한다. 멱등 확정 응답은 원래 성공 결과를 반환한다.

## 과거 회차와 기존 무효화 데이터

시작 회차를 포함해 그 이후 확정 이력이 있으면 새 자동 순차 분석을 시작할 수 없다. 미래 상태를 과거 기준으로 사용하는 것을 막는 검사는 유지하고 오류를 `ANALYSIS_FUTURE_HISTORY_CONFLICT`(400)로 구분한다. 일반적인 잘못된 mode/대상 조합은 기존 `ANALYSIS_RUN_MODE_INVALID`를 사용한다.

프론트는 지속적으로 불가능한 자동 시작 요청을 같은 버튼으로 반복하지 않고 원고 목록의 개별 `MANUAL + CONFIRMED_ONLY` 분석으로 안내한다. 업로드와 분석 생성이 별도 요청이므로 원고 저장이 성공했다면 그 사실을 알리고 재업로드를 요구하지 않는다. 자동 분석을 직접 검토로 조용히 바꾸거나 추가 유료 분석을 자동 시작하지 않는다.

원고 목록의 응답은 최신 ordered Job을 다음과 같이 표시한다.

- journal INVALIDATED: `analysisStatus=REANALYSIS_REQUIRED`
- SUCCEEDED여도 journal 미완성 또는 자동 반영 미완료: `analysisStatus=FAILED`
- 나머지는 기존 상태 판정 적용

원고 목록에서 이미 완료로 저장된 회차도 최신 분석이 무효화됐다면 명시적인 직접 검토 재분석에 진입할 수 있다. 기존 Job의 실행 결과와 journal을 일괄 정상화하지 않으며 현재 확정 설정도 소급해서 되돌리지 않는다.

## 비교 진행과 사용량 부족의 재개 안내

세계관 후보 응답의 선택적 `sourceAnalysisJobStatus`와 `sourceAnalysisJournalStatus`는 후보를 만든 원본 Job의 현재 상태다. 비교 후보의 `PENDING`이나 별도 `WORLD_SETTING_COMPARISON` 작업 수만으로 순차 원본 분석이 중단됐다고 추측하지 않는다. 두 필드는 기존 Job에서 파생하며 별도 상태 저장이나 DB migration은 추가하지 않는다.

일반 `CONFIRMED_ONLY`의 사용량 부족은 기존 배치의 남은 비교 재개 API를 사용한다. `ORDERED_PROVISIONAL`은 기존 회차 Job을 재개하며 남은 비교 API로 전환하지 않는다. 후보 목록과 분석 배치 목록의 재개 가능 표시는 같은 배치 전체 집계로 판단하고, 사용량 부족 후보 중 순차 분석 또는 자동 반영 진행 후보가 있으면 비교 재개를 허용한다고 표시하지 않는다. 필터·페이지 밖 후보도 포함해 실행 API의 거절 조건과 맞춘다. 사용량 실제 잔액과 실행 직전 상태는 재개 트랜잭션에서 다시 검사한다.

## 유지하는 안전 경계와 제한

- 원고 수정·회차 번호 변경·파일 교체·삭제의 해당 원문과 미완료 입력 보호, 원문 근거 파기, 소유권 및 lease 검증을 유지한다. 완료된 후행 결과를 보존하더라도 원문 변경 영향을 AI로 소급 재검증하거나 과거 상태를 재구성하지 않는다.
- 실행 직전 서버가 작품과 원문 상태를 검증한다. 화면 안내만으로 미래 확정 이력이나 비용 검사를 우회할 수 없다.
- 이미 사용한 토큰은 복구하지 않으며 추가 분석은 사용자가 명시적으로 선택한다.
- 실패한 앞 회차 때문에 후행 PENDING이 남으면 후보 검토는 계속 대기한다. 토큰 부족이나 반복 실패로 재개할 수 없는 경우에도 이번 변경은 취소/부분 검토 수단을 추가하지 않는다.
- 서로 다른 run 사이의 작품 전체 회차 순서 강제는 이번 변경에서 추가하지 않는다. 각 run의 predecessor와 기존 작품 RUNNING 제약을 유지한다.
- API 밖에서 운영 DB를 직접 수정하는 작업은 직접 설정 편집의 보호 계약에 포함되지 않는다.
