# GH199 늦은 후보 검토와 개인 이미지

관련 이슈: https://github.com/catchhole-soma/catchhole-backend-java/issues/199

## 확정 정책

앞 회차의 후보를 늦게 편집·연결·확정·제외해도 이미 완료된 뒤 회차의 분석 기록과 저장값은 취소하지 않는다. 저장된 분석 입력은 당시 기록으로 유지하며, 다음에 새로 시작하는 분석만 새 현재 설정과 수정된 미확정 참고 정보를 읽는다. 추가 LLM 호출이나 자동 재분석은 없다. 원고 삭제·교체 및 작품 설정 직접 수정 등 별도 무효화 원인은 이 변경에 포함하지 않는다.

완료된 순차 분석의 후보 확정은 자동/직접 검토 모드 모두 동일하게 다음을 적용한다. 작업 잠금으로 자동 반영과 사용자 확정을 직렬화하고 현재 대상의 해당 항목을 확인한다. 같은 세계관 대상의 묶음 확정은 확정 이력을 한 번 읽어 재사용한다. 전체 원고·회차의 텍스트 검색은 하지 않는다.

| 현재 상태 | 앞 회차 후보를 늦게 확정한 결과 |
|---|---|
| 같은 인물·항목 또는 같은 세계관 대상·범위·항목에 뒤 회차 값 존재 | 현재 값 유지, 후보는 원래 회차의 이력으로 저장 |
| 같은 값 또는 같은 회차의 상충값 | 이미 적용된 현재 값 유지, 추가 이력만 저장 |
| 사람이 직접 수정했거나 현재값의 근거를 확인할 수 없음 | 현재 값 유지, 이력만 저장 |
| 현재 값이 비었지만 해당 항목의 적용 기록이 남음 | 제거된 것으로 보수적으로 취급, 이력만 저장 |
| 해당 항목이 없고 적용 기록도 없음 | 현재 설정에 추가, 원래 근거 회차 유지 |
| 현재 값의 확인 가능한 모든 근거가 후보보다 앞 회차 | 후보의 확인된 값으로 현재 설정 갱신 |
| 캐릭터의 명시적인 과거·가정·시점 불명 상태 또는 이력 저장 선택 | 빈 항목이어도 이력만 저장 |
| 다른 항목/다른 세계관 범위 | 각각 독립 판단; 구조 충돌이 있으면 이력만 저장 |

현재값 보호를 위해 과거의 유용한 보완 설명도 자동으로 합치지 않는다. 캐릭터에서는 오래된 비교의 부수 삭제·병합 결과를 재실행하지 않고 사용자가 확인한 후보 값만 사용한다. 세계관의 범위 이동도 늦은 확정에 자동 재실행하지 않는다. 이력만 저장한 세계관 후보는 현재 설정의 근거·다음 분석의 기준 회차에서 제외하고 상세 이력에는 남긴다. 이력 저장 여부를 후보 응답 `historyOnly`로 제공한다.

같은 회차에서 여러 값이 경쟁하면 이미 확정된 현재값을 보호한다. 아직 값이 없다면 묶음 안의 회차·후보 순서에 따라 최초 반영된 값을 유지하고 이후 상충값은 이력에 남긴다. 자동으로 모순을 해소하는 기능은 제공하지 않는다.

연속 분석 작업이 진행·대기 중이면 후보 변경은 `ANALYSIS_REVIEW_WAIT_REQUIRED`(409)로 잠시 제한한다. 메시지: “연속 분석이 끝나면 이 설정을 수정·확정할 수 있습니다. 진행 중인 분석은 계속됩니다.” 원본 회차 자체의 자동 반영 대기는 기존 오류를 유지한다. 편집 초안을 자동 예약하거나 뒤 회차에 소급 전파하지 않는다.

## 현재 설정 보호의 저장 근거

- 캐릭터: 현재 항목과 그 근거 Fact의 회차/사용자 수정 여부를 확인한다. 항목이 없으면 동일 인물·항목의 기존 Fact로 제거 흔적을 확인한다. 이력 전용으로만 생성된 Fact는 제거 흔적으로 보지 않는다.
- 세계관: 동일 대상의 확정 후보를 범위·항목으로 구분하고 이력 전용 후보를 제외한다. 현재값과 근거가 일치하지 않거나 근거가 없으면 보호한다. 새 직접 수정에는 경로별 보호 표시를 남긴다. 이름 변경은 이전 경로와 새 경로 모두 표시한다.
- 기존 데이터에서 삭제/수정 시점을 완벽하게 복원하지 못하는 경우에는 현재값 보호를 우선한다. 이전에 무효화된 분석 기록을 일괄 정상화하지 않는다.

## 이미지 API와 배포

새 multipart 업로드는 `metadata: {id, name}`, PNG `image`, PNG `thumbnail`을 받는다. 기존 `vaultId + encryptedMetadata` 방식은 CHI1 호환용으로 유지한다. 두 방식을 혼합하면 거절한다. 새 이미지 응답은 `name`이 있고 `vaultId`가 없다.

브라우저는 PNG/JPEG/WebP를 읽어 메타데이터를 제외한 PNG/썸네일을 만든다. 서버는 PNG 실제 내용·크기·해상도를 검증하고 다시 인코딩한다. 원본 5MiB, 썸네일 512KiB/480px, 전체 3,200만 화소/한 변 16,384px, 작품당 50개 제한을 유지한다.

업로드·목록·파일·삭제·대표 이미지 선택은 로그인 및 작품 소유권을 검증한다. 파일은 기존 비공개 작품 경로에 저장하며 공개 URL/도감에 등록하지 않는다. 조회는 인증 API와 `Cache-Control: private, no-store`, `nosniff`를 사용한다. 기존 업로드 예약·실패 정리·삭제 재시도와 사용 중 삭제 거절을 유지한다. 새 파일과 이름은 서버가 처리할 수 있으므로 종단간 암호화를 보장한다고 설명하지 않는다.

V67은 기존 암호화 이미지 행을 보존하면서 계정 방식의 메타데이터를 허용한다. V68은 세계관 이력 전용 표시와 직접 수정 경로를 추가한다. Java를 먼저 배포한 뒤 생성 SDK를 포함한 프론트를 배포한다. 이전 프론트의 암호화 업로드도 계속 수용한다. 새 프론트에서는 기존 암호화 이미지를 지우거나 강제 변환하지 않고 원본 재업로드·교체를 안내한다. 키가 없는 서버에서 기존 암호문을 자동 변환할 수 없다. DB 롤백으로 새 형식 행을 예전 NOT NULL 제약에 넣으면 안 된다.

## 검증

`AutomaticAnalysisIntegrationTest`의 단건/묶음 늦은 확정은 최신값·삭제·수동값·빈 항목·과거 상태·새 세계관 범위를 검증하고, 다음 분석 입력에 이력 전용 값이 섞이지 않는지 확인한다. 후보 편집 후 이미 완료된 분석의 상태와 입력 해시 보존, 진행 중 편집 거절, 동일 요청 재시도도 검증한다.

`PrivateWorldImageIntegrationTest`는 새/기존 방식 왕복, 보관함 없이 업로드, 타인 계정/작품 접근 거절, 잘못된 파일·크기 제한과 기존 저장 실패/정리 계약을 검증한다. 프론트 Playwright는 실제 로컬 서버의 일회용 계정으로 캐릭터·세계관 공유, 업로드·선택·새로고침·삭제와 미인증 접근 차단을 검증한다. 운영 저장소나 실제 사용자 작품을 테스트용으로 변경하지 않는다.

- 실제 브라우저 연동 2건: 새 방식 이미지 업로드·선택·새로고침, 캐릭터/세계관 공유, 사용 중 삭제 거절·미인증 차단·삭제 확인. 일회용 계정과 작품 정리 완료.

이미지 용량 정책 추가 결정: 작품당 50개는 유지하며 신규 업로드는 파일당 5MiB로 제한한다. 이전 암호화 업로드에는 32바이트 부가정보만 추가 허용한다. 기존에 저장한 5MiB 초과 이미지를 삭제하거나 조회를 제한하지 않는다. 정확한 한도와 1바이트 초과를 API 통합 테스트로 검증한다.

## PR 전 최종 점검

- 이미 확정한 단건/묶음 요청을 다시 받으면 동일한 결과를 반환한다. 다음 회차가 새로 대기·진행 중이어도 완료된 요청의 재시도는 거절하지 않는다. 아직 반영하지 않은 후보 변경의 잠금과 다른 결정으로 재확정하는 충돌 검증은 유지한다.
- 완료된 회차의 후보 값·연결을 편집해도 과거/가정/시점 불명 구분과 이력 전용/해제 판단을 보존한다. 편집으로 기존 제안 내용을 지울 때 이 구분까지 사라져 빈 현재 항목에 과거 상태가 들어가는 것을 방지한다. 테스트는 편집 전 판단을 설정하고 실제 연결·편집·단건/묶음 확정 후 다음 분석 입력까지 확인한다.
- 기존 암호화 업로드에서 필요한 암호화 정보가 빠지면 저장 전에 400을 반환한다. 새 업로드에서 선택 필드로 바뀐 값이 예전 처리 경로에서 서버 오류를 일으키지 않도록 한다.
- 프론트는 계정/작품 전환 시 이전 업로드의 처리 잠금을 정리하고, 늦게 도착한 응답이 새 창의 선택·오류·처리 상태를 바꾸지 않게 한다.

### 유지한 경계와 제한

진행·대기 중인 순차 분석이 있는 동안 새 후보 수정은 잠시 제한한다. 실패한 앞 회차 때문에 뒤 회차가 대기 중인 경우에도 재개 또는 취소로 대기를 정리한 뒤 수정한다. 이 제한은 사용자 변경 요청에만 적용하며 Worker가 다음 회차를 처리하는 조건을 강화하지 않는다. 원문 버전 불일치, 소유권, 대상 연결 불명확, 값 타입 오류는 임의로 통과시키지 않는다. 원고 교체나 작품 설정 DB 직접 수정에 따른 기존 무효화 정책은 별도 범위로 유지한다.

최종 점검 후 전체 Java 테스트: 총 1,236건 중 1,170건 통과, 환경 조건부 66건 제외, 실패 0건. `./gradlew test bootJar` 성공. 프론트 관련 브라우저 회귀 91건 통과 및 이미지 3건 최종 재검증, 빌드·ESLint·Knip 통과(기존 ESLint 경고 2건).
