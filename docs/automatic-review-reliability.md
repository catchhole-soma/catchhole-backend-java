# 순차 자동 분석의 오류 격리와 직접 검토 안내

GH-180 · 2026-09-11

## 목적과 적용 범위

한 회차에서 설정 하나의 비교가 잘못됐다고 다른 정상 설정까지 잃지 않게 한다. 업로드 묶음을 나눠도
앞 회차의 유효한 미확정 정보를 참고하고, 자동으로 반영하지 못한 이유를 사용자가 이해할 수 있게 보여준다.
이는 오류 격리와 검토 흐름의 개선이며 실제 소설의 정답률·재현율을 높였다는 측정 결과는 아니다.

새 단일 회차와 다회차의 자동 반영 기본값, 원고 합계 250,000자 제한, 순차 저장 이후 다음 회차 시작,
작품 소유권·작업 권한·입력 일치·현재 설정 검증은 유지한다. 직접 검토를 선택할 수 있다.

## 1. 이전 업로드 묶음의 미확정 참고

자동 분석은 각 회차 시작 직전에 실제 저장된 설정을 읽고, 같은 작품의 앞 회차 대기 후보를 별도로 읽는다.
같은 업로드 묶음으로 한정하지 않는다. 회차별 최신 추출 작업을 먼저 선택하고 유효한 원문·성공 상태·대기
후보·원문 인용을 확인한다. 최신 작업이 실패했을 때 예전 성공 결과로 돌아가지 않는다.

확정·제외·원문 삭제/교체·진행 중인 비교·인용이 없는 후보는 참고하지 않는다. 실패한 비교는 추출값과
원문만 전달하고 잘못된 대상 선택이나 제안값을 복사하지 않는다. 정상 범위 검토는 원본/기존 범위를 보존하고
서버가 정한 자연어로 보류 종류를 설명한다. 모델이 작성했던 판단 문장을 다시 권위 있는 근거로 사용하지 않는다.

사용자가 수정해 원분석이 무효화됐더라도 현재 원문과 인용이 유효한 명시적 수정 내용은 참고할 수 있다.
수정 전 AI 제안으로 되돌리지 않으며, 인용은 수정 전 원문이라는 점을 안내한다. 제외 수정안이나 비어 있는
수정값, 보관된 인물은 제외한다. 미확정 참고를 등록된 대상 목록에 넣거나 확정 사실로 저장하지 않는다.
후속 결론도 현재 회차 자체의 근거와 기존 비교 검증을 통과해야 한다.

회차가 시작하면 참고 목록까지 입력과 hash에 고정한다. 사용자 수정·확정·제외·원문 파기는 기존 작품 잠금과
후속 회차 무효화 경로를 사용하므로 다른 업로드 묶음에 이미 시작한 분석도 변경을 무시하지 않는다.
기존 입력·hash·변경 기록은 수정 내용으로 덮어쓰지 않는다. 세부 규칙은 [순차 분석 문서](ordered-provisional-analysis.md)를 따른다.

## 2. 캐릭터 비교의 정상 항목 보존

캐릭터 비교는 같은 인물의 같은 설정 분류를 원문 순서대로 묶는다. 기존 재시도가 모두 실패하면 마지막
응답만 대상으로 각 결과를 다시 검증한다. 원본 후보 수·순서·식별이 맞지 않으면 일부를 임의로 골라 믿지 않는다.
정상처럼 보인다는 이유만으로 검증 없이 저장하지 않는다.

원문 위치는 실제 추출 저장 형식인 `start_offset`과 구형 `startOffset`을 모두 읽는다. 후보가 같은 시각에
저장되더라도 원문 위치를 먼저 사용하고, 위치가 같거나 없을 때만 생성 시각과 식별자로 순서를 고정한다.
이는 새 묶음을 만들기 전의 순서다. 이미 비교 묶음에 배정한 후보는 묶음 생성 순서와 저장된 후보 참조
순서를 문맥 조회·완료·이전 결정 재적용·그룹 확정에서도 보존한다. 원문 위치 해석을 고쳤다는 이유로
기존 완료 결과의 문맥 hash나 선행 의존을 바꾸지 않는다. 누락·중복된 참조와 실제 설정 변경은 기존처럼 거절한다.

기존 근거 JSON·확정 사실·변경 기록을 다시 쓰지 않는다. 중단된 비교를 재개할 때는 실패 후보의 이전
묶음 연결과 임시 참조를 지운 다음 새 묶음에서 다시 부여하므로 새 순서를 과거 참조에 억지로 적용하지 않는다.

독립적으로 검증할 수 있는 항목은 보존한다. 실패한 설정 항목에 의존하거나 같은 항목을 뒤에서 다시 바꾸는
결과는 그대로 보존하지 않고 다시 비교한다. 상태 설정은 다른 상태의 해제·이름 변경도 가능하므로 중간 상태
판단이 실패하면 뒤 상태 후보 전체를 다시 검토한다. 보존하지 못한 후보는 고정 문맥에서 한 번씩 추가 비교하며,
작업 권한·사용량·입력 오류는 개별 후보 실패로 바꾸어 넘기지 않는다. 정상 응답의 호출 수는 늘리지 않는다.

Java 완료 API는 정상 결정과 실패 목록이 원본 후보 전체를 중복 없이 정확하게 덮는지 확인한다. 정상 결정은
기존 설정 경로·값·선행 의존·제거 검증을 모두 통과해야 한다. 실패한 후보의 임시 결과를 참조할 수 없다.
정상 결정에 사용량 부족·입력 오류·작업 권한 오류·예상 밖 오류를 섞은 완료 요청은 거절한다. 저장은 한
트랜잭션이며 같은 완료 내용의 재전송은 멱등하게 처리한다.

| 실행 방식 | 묶음 일부 실패 시 저장 | 다음 묶음·회차 |
| --- | --- | --- |
| 순차 자동 반영 | 검증된 정상 비교와 실패 후보를 함께 보존하고 정상 설정을 자동 반영 | 격리 가능한 비교 실패이면 계속 진행 |
| 순차 직접 검토 | 검증된 정상 비교는 보존하되 자동으로 작품 설정에 반영하지 않음 | 실패가 남으면 기존 중단·재개 정책 유지 |
| 기존 비순차 비교 | 기존 비교·복구 정책 유지 | 기존 정책 유지 |

세계관의 기존 속성 선택과 독립 묶음 복구는 [세계관 비교 복구 문서](world-comparison-recovery.md)를 따른다.
두 도메인 모두 저장 장애·입력 불일치·작업 권한 상실을 무시하고 다음 회차로 넘어가는 기능은 아니다.

## 3. 같은 이름의 신규 세계관 대상

대상을 연결하는 단계에서 새 대상을 발견하면 해당 원문 후보를 출처로 하는 임시 대상을 같은 분류의 선택
목록에 추가한다. 뒤 후보는 그 대상의 이름과 원문 근거를 보고 같은 개념·존재인지 판단할 수 있다.
같은 대상을 선택한 경우에만 그 대상에 새 근거를 덧붙인다. 아직 확정하지 않았거나 비교할 특성이 다르다는
이유만으로 매번 별개의 대상을 만들지 않도록 요청한다.

이름 일치만으로 합치는 규칙은 아니다. 서로 다른 장소·개별 존재이거나 연결이 모호하면 분리/보류한다.
미확정 참고 문장 자체는 선택 가능한 대상이 아니다. 실제 대상과 임시 대상의 구분, 후보 소유권과 원문 출처,
비교 후 실제 저장 시 동일 대상 확인은 그대로 유지한다. 저장 직전에 이름만 보고 다른 대상으로 강제 병합하지 않는다.

## 4. 자동 반영 보류와 사용자 안내

### 비교 상태와 저장 보류를 구분

`automatic_review_hold_reason`은 비교 결과와 별도로 기록하는 자동 반영 보류 사유다. 자동 반영 중
현재 설정이 달라졌거나 동일 대상인지 다시 확인해야 한다고 해서 원래 AI의 `ADD`/`UPDATE`를
`REVIEW_REQUIRED`로 덮거나 정상 `COMPLETED`를 `FAILED`로 바꾸지 않는다.

| API 사유 | 사용자에게 안내할 의미 |
| --- | --- |
| `SUBJECT_RESOLUTION_FAILED` | 연결 판단을 완료하지 못해 원문과 대상을 확인 |
| `COMPARISON_INPUT_TOO_LARGE` | 비교할 내용이 많아 해당 설정을 직접 확인 |
| `SUBJECT_CONFIRMATION_REQUIRED` | 이 설정들이 같은 대상을 설명하는지 확인 |
| `DEPENDENCY_CONFIRMATION_REQUIRED` | 먼저 확인해야 할 관련 설정이 남음 |
| `CURRENT_SETTING_CHANGED` | 비교 이후 기존 설정이 바뀌어 현재 내용과 제안 확인 |
| `SETTING_VALUE_CONFIRMATION_REQUIRED` | 저장할 설정의 분류와 내용 확인 |
| `SETTING_LOCATION_CONFLICT` | 어느 설정 항목에 반영할지 확인 |
| `REVIEW_REQUIRED` | 원문과 제안을 직접 확인해야 하는 일반 보류 |

사유는 검토 대기 후보에만 공개하며 과거 사유가 없으면 임의로 추측하지 않는다. 수정·연결 변경·새 비교에서
오래된 사유를 지우고, 검토가 끝난 후보에는 보류 안내를 노출하지 않는다. 화면 문장이 매끄럽지 않다는 이유로
분석 실패나 유료 재시도 조건을 새로 추가하지 않는다.

보류 표시가 수동 확정의 검증을 대신하지도 않는다. 캐릭터 단건·그룹 확정은 인물 연결, 같은 인물의 선행
확정, 현재 설정, 값 형식과 제거 대상의 저장 시점을 다시 검증한다. 세계관도 실제 대상·기존값·전체 경로를
순차 검증한다. 명시적 사용자 수정 적용만 현재 대상과 작성 기준으로 다시 판단하며, 이를 AI 비교 성공으로
위장하지 않는다.

### 묶음 전체 검토 집계

캐릭터·세계관 목록은 다음 네 개를 필수 `int64`로 제공한다. 필터와 현재 페이지의 항목 수로 추산하지 않고
해당 작품·업로드 묶음 전체에서 한 번씩 계산한다.

| 필드 | 화면 의미 | 집계 |
| --- | --- | --- |
| `confirmedCandidateCount` | 반영 | 확정된 후보. 이력에만 저장한 후보도 포함 |
| `dismissedCandidateCount` | 제외 | 제외된 후보 |
| `directReviewCandidateCount` | 직접 확인 | 미확정이면서 비교 대기/진행도 아니고 회차 자동 반영 대기도 아닌 후보 |
| `processingCandidateCount` | 분석·반영 중 | 미확정이면서 비교 `PENDING`/`PROCESSING`이거나 회차 자동 반영을 기다리는 후보 |

네 값의 합은 전체 후보 수와 같다. 직접 확인과 비교 대기·진행의 합은 미확정 후보 수이며, 반영과 제외의 합은
검토 완료 수다. 이유가 여러 개여도 후보는 한 번만 센다. 캐릭터 연결 필요 수와 예전 제한된 확인 필요 수는
호환용으로 유지하지만, 새로운 전체 직접 확인 요약은 `directReviewCandidateCount`를 사용한다.

### 자동 반영이 끝나기 전의 후보

한 회차의 비교가 일부 끝났더라도 회차 전체 분석과 자동 저장은 아직 진행 중일 수 있다. 이때 완료된 비교를
바로 직접 확인 대상으로 보여 주면 사용자가 수정하면서 진행 중인 회차와 뒤 회차를 무효화할 수 있다.
두 후보 응답의 필수 boolean `automaticApplicationPending`으로 이 상태를 별도 표시한다. 계산 조건은
검토 대기 후보이고, 원본 작업의 검토 방식이 `AUTOMATIC`이며, `automaticAppliedAt`이 없고 작업 상태가
`PENDING` 또는 `RUNNING`인 경우다. 비교가 완료되었거나 실패했는지와 무관하게 적용한다.

이 후보는 네 집계에서 진행 중에 포함하며 직접 확인 수에서는 제외한다. 화면은 자동 반영을 기다린다는
안내를 보여 주고 수정·연결·확정·제외·재비교 버튼을 잠근다. 서버도 같은 작품 잠금을 잡은 뒤 선택한 후보의
원본 작업을 확인하여, 변경이나 후속 분석 무효화 전에 `409 / ANALYSIS_AUTOMATIC_APPLICATION_PENDING`으로
거절한다. 안내 문장은 “이 회차의 설정을 자동으로 반영하고 있습니다. 완료된 뒤 다시 시도해 주세요.”다.
자동 완료도 작품을 먼저 잠그므로 자동 저장과 수동 변경의 경계를 직렬화한다.

이미 검토한 후보, 수동 분석, 실패·취소·종료된 작업과 자동 반영 시각이 기록된 앞 회차는 이 잠금 대상이
아니다. 완료된 앞 회차의 보류 후보를 사용자가 변경하면 기존처럼 영향받는 후속 분석을 무효화한다.
이 보호를 작품 전체의 이름 변경 금지나 영구 수정 금지로 확장하지 않는다. 새 DB 컬럼이나 migration은 필요 없다.

### 자연어 표현 원칙

오류와 AI 판단 문장은 사용자가 무엇을 확인해야 하는지 설명한다. 내부 저장 구조·필드명·참조 번호·enum을
사용자에게 학습시키지 않는다. 예를 들어 내부 최상위 위치에 포함한다는 설명은 “별도 구분 없이 정리합니다”,
설정 저장본을 뜻하는 표현은 “현재 설정”, 값의 저장 자리를 뜻하는 표현은 “설정 항목”으로 설명한다.

AI 요청에는 처음부터 이 원칙을 적용한다. 과거 기록도 공개 응답을 만들 때만 표현을 정리한다.
실제 인물·대상·속성 이름이나 원문·설정값이 기술 단어와 같으면 작품 내용을 우선 보존한다. 알 수 없는 내부
식별자의 뜻을 추측해 대상명이나 판단 근거를 만들어 내지 않고 중립적인 확인 안내를 사용한다.
원문 인용·추출값·제안값·저장된 AI 응답·비교 판단은 원본으로 유지한다.

용어 검사도 문맥을 확인한다. 예를 들어 “짐승의 소굴 루트의 출발 지점”과 “강철바위언덕의 루트상 위치”의
루트는 이동 경로를 뜻하므로 개발 용어 노출이 아니다. 이런 문장을 저장 구조의 최상위 위치를 뜻하는 표현과
같이 치환하지 않는다. 단어 검색 결과만으로 오류나 문장 변경 대상으로 확정하지 않는다.

문장을 다듬는 처리와 기존 응답 검증은 구분한다. `root`, `slot`, `snapshot` 같은 설명 표현을 더 자연스럽게
만들기 위해 새 실패 조건을 추가하지 않는다. 반면 실제 ID·알 수 없는 참조·내부 enum 노출을 거절하던 AI의
기존 검증은 유지한다. 특히 입력에 없는 대상이나 아직 만들어지지 않은 설정을 근거로 쓴 응답의 일관성
검증을 해제하지 않는다. 새 응답의 검증과 과거 기록을 공개할 때 안전한 안내로 정리하는 처리는 다른 경계다.

## 5. 비교 판단과 자동 저장의 검증 일치

### 새 인물의 과거 상태

새로 발견한 인물의 등록과 그 인물에게 일어난 사건의 현재 반영 여부는 별개다. 새 인물에게도 이미 끝난
기절처럼 `HISTORY_ONLY + PAST`인 설정을 이력으로 저장할 수 있다. 자동 반영의 `APPLY_PROPOSAL`은
비교에서 제안한 처리를 따른다는 뜻이며, 모든 설정을 현재 상태에 추가한다는 뜻이 아니다.

인물 연결 전 사전 검증은 실제 인물 연결·반영 경로와 같은 기준으로 비교 연산을 결정한다. 순차 분석의
임시 인물이나 작가가 수정한 신규 인물은 아직 실제 인물 ID가 없더라도 비교 판단을 보존한다. 신규 인물
묶음 확정도 실제 묶음 반영 경로와 동일하게 판정한다. 기존 비순차 신규 인물 처리 방식은 유지한다.

따라서 이력만 저장한 끝난 상태는 현재 설정과 다음 회차의 활성 상태 목록에 추가되지 않는다. 실제로
비활성 상태를 `ADD/UPDATE/MERGE`로 현재 설정에 쓰려는 요청은 원본·제안 어느 쪽에 비활성 표시가
있더라도 계속 거절한다. 실제 대상·현재 값·제거 대상·입력 버전 검사도 생략하지 않는다.

### 같은 회차의 변경 후 중복 제외

세계관에서 먼저 처리한 비교 묶음이 어떤 값을 변경하고 뒤 묶음이 그 새 값과 같아 `EXCLUDE`된 경우,
뒤 판단의 비교 기준은 회차 시작 값이 아니라 해당 비교 묶음이 시작할 당시까지 계산한 값이다. 반면 같은
비교 묶음 안의 판단들은 동일한 고정 입력을 사용한다. 같은 묶음의 앞 UPDATE를 EXCLUDE의 기존값에
미리 반영해서도 안 된다.

자동 저장 전 제외 검증은 각 결정에 저장된 비교 기준 버전보다 작은 버전의 변경만 선택하고 같은 비교
묶음의 변경은 제외한다. 원문 근거 위치와 실제 비교 묶음 처리 순서가 엇갈려도 이 구분을 유지한다. 선택한
이전 변경을 기존 저장 검증으로 계산한 뒤 정확한 대상·범위·설정명에 해당하는 값을 대조한다. 하나의 제외
판단을 여러 원문 후보가 공유해도 결정당 한 번 검증한다. 비교 기준 버전이 없으면 임의로 추정하지 않는다.

자동 반영의 기준 복원과 최종 설정 계산은 모두 비교 기준 버전 순으로 변경을 적용한다. 같은 버전 안에서는
기존 원문 순서를 유지한다. 여러 이전 묶음에서 설정 위치 이동 뒤 그 속성을 수정한 경우에도 이동이 먼저
계산되어야 한다. 수동 확정은 기존 원문 순서를 유지하며 이 자동 전용 순서를 적용하지 않는다. 정렬만 별도
경로로 두고 실제 대상·기존값·속성 충돌·이동 검증은 같은 처리로 재사용한다.

이 계산은 검증용 메모리에서만 수행하고 모든 검증을 통과하기 전에는 설정을 쓰지 않는다. 실제 기존값이
바뀌었거나 다른 임시 대상의 값을 가져온 경우, 해당 속성이 없거나 뒤의 ADD를 앞당겨야만 성립하는
경우는 계속 보류한다. 처음 만드는 세계관 대상도 같은 대상의 선행 ADD가 해당 값을 만든 경우에만
후행 제외를 허용한다. 기존에는 이런 정상 결과도 묶음 전체가 현재값 변경으로 보류될 수 있었다.

### 저장 단계 실패와 재개 진단

AI Worker는 작업을 다시 가져올 때 기존 표시 단계를 무조건 추출로 덮지 않는다. 저장된 체크포인트에
맞는 실제 다음 단계부터 진행하고, 최종 서버 저장·자동 반영 요청 직전에는 `PERSISTING`을 기록한다.
추출·비교가 끝난 작업의 최종 저장이 거절되면 API·로그에 저장 단계 실패로 남는다. 현재 프론트는 이
문자열을 직접 표시하지 않으므로 이 변경만으로 화면에 별도 저장 단계가 생기지는 않는다.

비교 후보의 격리 가능한 응답 실패와 서버 저장 오류는 계속 구분한다. 서버 저장 규칙의 결함이나 입력·
작업 권한·사용량 오류를 무시하고 다음 회차로 넘기지 않는다. 최종 자동 반영은 원자적으로 롤백하고,
수정 후 같은 완료 체크포인트에서 재개하여 기존 추출·비교를 반복하지 않도록 검증한다.

이 변경은 분석 입력을 줄이거나 AI 판단 규칙을 변경하는 최적화가 아니다. 문맥 중복 제거·선별·대상 연결
묶음은 [별도 이슈 #187](https://github.com/catchhole-soma/catchhole-backend-java/issues/187)의 품질 평가를 거친다.

## 데이터와 배포

V52는 캐릭터·세계관 후보 테이블에 nullable 보류 사유 컬럼만 추가한다. 과거 후보에는 사유를 채우지 않으며
기존 성공·실패·확정·제외·원문·설정값·입력/hash·변경 기록을 고치지 않는다. 이미 끝난 1~32화를 자동으로
다시 분석하거나 확정하지 않는다. 새로운 참고 수집과 비교 복구는 새로 처리하는 요청부터 적용한다.

Java·AI·프론트 계약과 생성 클라이언트를 함께 갱신한다. 새 네 집계는 필수 응답이며 보류 사유는 선택
nullable enum이므로 기존 NULL 기록과 호환된다. 실행 중인 서버를 갱신할 때 데이터 볼륨을 보존하고,
활성 작업을 정리한 뒤 코드와 migration이 일치하는지 검증한다. 이 문서는 운영 배포 완료를 뜻하지 않는다.

## 검증 기준

- 앞 회차 참고: 다른 묶음, 최신 작업 우선, 원문 교체/삭제, 미래/다른 작품, 사용자 수정, 입력 고정 및 무효화.
- 비교 복구: 정상 항목 유지, 실패 항목과 의존 항목 차단, 상태 해제 영향, 전체 후보 포함, 재전송, 작업 오류 차단.
- 비교 순서: 실제/구형 원문 위치 호환, 같은 생성 시각·반대 UUID, 이미 배정한 참조와 반대인 원문 위치, 기존 완료 문맥·그룹 확정의 선행 의존 보존, 여러 묶음과 미배정 후보를 섞은 입력 순열, 깨진 참조 거절.
- 자동 보류: 기존 비교 operation/근거 보존, 보류 사유의 분리, 수동 확정에서 현재 대상·값·의존 재검증.
- 신규 인물: 끝난 상태의 이력 전용 자동 저장, 발견 선행 유무, 신규 인물 묶음·작가 수정 경로, 실제 비활성 현재 반영 거절, 최종 저장 롤백·재시도와 다음 회차 상태 보존.
- 세계관 제외: 이전 비교 묶음의 변경·신규 추가·범위 이동 후 제외 허용, 같은 묶음의 고정 시작 기준 유지, 공유 결정과 원문 위치/비교 순서 역전, 실제 기존값 변경·다른 대상·없는 속성·후행 추가 소급은 보류.
- 재개 진단: 완료된 추출·비교 반복 금지, 실제 비교 재개 단계 표시, 최종 저장 거절은 저장 단계로 기록.
- 집계: 필터·페이지 독립, 복수 보류 사유 중복 제거, 검토 완료 후보 제외, 네 분류의 합계.
- 자동 반영 대기: 원본 작업의 모드·상태·반영 시각별 flag/집계, 단건·그룹 변경 409, 거절 시 입력·후속 작업 보존, 완료된 앞 회차의 기존 수정 정책.
- 표현: 개발 문구 정리, 실제 작품 이름 보호, 미해석 식별자의 중립 안내, 원문 데이터와 분석 상태 미변경.
- OpenAPI: 두 목록의 필수 집계 네 개, 두 후보의 선택 nullable 보류 enum, 기존 비교 필드 보존.

검증은 격리 H2/전용 PostgreSQL과 고정 AI 응답을 사용한다. 테스트 통과는 계약과 저장 경계에 대한 증거이며
실제 모델의 추출 정확도 또는 모든 입력에서의 무오류를 보증하지 않는다.


## 6. 비교 이전과 최종 저장의 실패 격리 보완 (2026-09-11)

한 후보의 오류가 전체 회차로 전파되던 다음 경계를 자동 순차 모드에서 보완했다.

| 발생 위치 | 보완된 처리 | 보존하는 정보 |
| --- | --- | --- |
| 세계관 대상 연결 | 제한된 호출 재시도 후 실패 후보만 보류, 뒤 후보 연결 계속 | 원본 값·근거, 실패 코드, 연결 실패 단계 |
| 선택적인 인물 연결 보강 | 보강이 필요했던 후보만 보류 | 이미 규칙으로 연결한 후보·인물 발견 유지 |
| 캐릭터 비교 준비 | 잘못된 설정 분류·값 형식은 해당 항목만 보류 | 원본 후보, 설정값 확인 안내 |
| 세계관 비교 묶음 상한 | 원문 순서대로 내부 분할 후 차례로 비교 | 앞 묶음의 정상 결정이 반영된 다음 비교 기준 |
| 기존 문맥이 너무 큰 비교 | 독립적으로 처리할 수 없는 후보/묶음만 보류 | 비교할 내용 확인 안내, 원본 내용 유지 |
| 캐릭터 최종 자동 저장 | 실제 적용과 같은 검증을 쓰기 전에 수행 | 정상 후보 저장, 실패 항목·의존 항목 확인 대기 |

연결 실패는 AI가 명시적으로 모호하다고 판단한 결과와 별개다. 세계관 API는 실패 시 선택 대상 없이
`failureCode`를 전달하고 `FAILED`로 반환한다. 실제 대상을 새로 만들거나 같은 이름에 강제 연결하지
않는다. 캐릭터도 실패한 연결 대상만 초기 후보에 기록한다. 후보의 실패 단계는 V53의 nullable
`preparation_failure_stage`에 저장하고, 기존 비교 실패 코드와 함께 판단한다. 과거 후보에 단계 값을
추정해서 채우지 않는다. 이후 저장 장애로 작업을 재개해도 이미 보류한 준비·비교 실패는 유지하여 같은 원문 후보의 실패 참고와 새 결정이 중복되지 않게 한다.

신뢰도는 0.65·0.8·0.95의 세 값만 요구하지 않고 유한한 0~1 원값을 허용한다. 값의 의미나 자동 저장
기준을 올리는 보정은 하지 않는다. 빠진 값, 범위 밖 값과 무한대는 유효한 신뢰도로 간주하지 않는다.

최종 자동 저장의 사전 검증은 실제 저장 검증과 같은 계획을 사용한다. 앞서 수용한 변경만 메모리에서
적용해 제거 대상·제안값·자료형을 점검한다. 이력 저장은 현재 설정을 바꾸지 않는다. DB 쓰기 자체가
실패하면 전체 완료 트랜잭션을 롤백하며, 예외를 잡고 부분 저장을 완료로 표시하지 않는다.

분석 목록은 작업 성공뿐 아니라 누적 기록 봉인과 자동 저장 완료를 함께 확인한다. 앞 회차의 실패로
막힌 대기 회차를 진행 중으로 세지 않는다. 검토 후보가 남아도 분석이 끝났으면 확인 가능한 개수로
안내하며, 사용자 수정이 뒤 회차를 중단시킬 수 있음을 수정·확정 화면에 미리 안내한다.

### 계속 중단해야 하는 경우와 후속 범위

원문 유실, 분석 기준 변경, 실행권 상실, 인증·결제·토큰 문제, 저장 장애와 전체 응답을 해석할 수 없는
1차 추출 실패는 후보 하나를 보류하는 것만으로 해결하지 않는다. 특히 인증/결제 제공자 오류를
일반 후보 비교 실패로 저장하여 다음 완료 요청에서 우회할 수 없도록 분류한다.

1차 추출의 부분 완료와 누락 원문 표시, 긴 간격의 제한된 자동 재개, 분석 중 수정 예약은 별도 상태
계약이 필요한 후속 범위다. 이번 변경은 회차를 몰래 건너뛰거나 모든 오류를 무조건 성공으로 바꾸지 않는다.
배포 순서는 V53을 포함한 Java/API, AI Worker, 생성 API 타입을 반영한 프론트다. 기존 데이터 볼륨과
완료한 실행의 원문·후보·고정 입력·변경 기록을 보존한다.
