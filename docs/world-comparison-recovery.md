# 순차 자동 분석의 세계관 비교 복구

2026-09-10 · GH180

## 해결하는 문제

기존 비교는 AI가 기존 설정의 대상, 범위, 속성명을 각각 작성했습니다. 예를 들어 `고블린 → 전투 → 무기`를 고르면서 `전투`만 보내면 비교 위치가 완성되지 않습니다. 이런 응답 하나가 여러 설정이 묶인 응답 검증을 실패시켰고, 재시도 후에도 고쳐지지 않으면 같은 묶음의 정상 후보도 함께 실패했습니다.

이번 변경은 기존 설정을 **완성된 속성 단위로 선택**하게 만들고, 순차 자동 분석에서 응답 오류가 남으면 **독립적으로 검증할 수 있는 후보를 다시 비교**해 보존합니다. 잘못된 응답에서 정상처럼 보이는 부분을 바로 꺼내 저장하지 않습니다.

실제로 어떤 기존 속성을 골랐는지는 예전 실패 기록에 남아 있지 않으므로, 과거 고블린 후보 중 특정 항목을 원인으로 단정하거나 새 진단을 소급 생성하지 않습니다.

## 처리 순서

1. 해당 회차 시작 시 확정 설정과 미확정 참고를 구분한 입력을 고정합니다.
2. 세계관 주체가 연결된 후보 묶음을 기존 방식대로 비교합니다. 후보가 여럿이라고 무조건 추가 호출하지 않습니다.
3. 기존 속성을 수정·병합할 때 AI는 입력에 있는 속성 참조 하나를 고릅니다. 코드가 대상·범위·속성명을 복원합니다.
4. 응답 파싱·출력 절단·응답 검증 오류는 기존 재시도 정책을 거칩니다.
5. 재시도가 소진되고 **순차 자동 분석의 다중 후보 묶음**이면 제한된 복구를 시작합니다.
6. 정상 결정과 실패 목록이 모든 원본 후보를 한 번씩 포함하는지 확인한 뒤, 한 완료 요청으로 원자 저장합니다.
7. 회차의 자동 확정 단계에서 정상 설정을 작품에 반영합니다. 실패·검토 필요 항목은 검토 대상으로 남기고, 다음 회차는 반영된 정상 설정과 남은 미확정 참고를 구분해 읽습니다.

이 문서의 세계관 내부 복구는 순차 자동 반영에 적용하며 수동 세계관·기존 비순차 비교의 실패 경계는 유지합니다.
후속으로 추가한 캐릭터 묶음의 정상 결과 보존, 이전 묶음 참고, 보류 사유와 화면 집계는
[자동 분석 신뢰성 문서](automatic-review-reliability.md)를 참고합니다.

## 기존 속성 선택 계약

입력의 각 속성에 `T1.P1` 같은 요청 내부 참조를 부여합니다. 응답 스키마에는 실제 입력에 있는 속성 참조만 선택지로 넣습니다. 응답을 받은 뒤에도 참조가 존재하고 선택한 대상에 속하는지 검증합니다.

| 판단 | AI가 전달하는 경로 | 코드의 처리 |
| --- | --- | --- |
| 추가 | 새 범위·속성명, 기존 속성 참조 없음 | 기존 경로 및 구조 충돌을 검증 |
| 수정·병합 | 기존 속성 참조, 제안 범위·속성명은 null | 선택한 기존 속성의 전체 경로를 복원 |
| 기존 내용과 중복이라 제외 | 비교한 기존 속성 참조 | 선택한 전체 경로를 검증·보존 |
| 내용 자체를 제외 | 기존 속성 참조 없음 | 연결된 주체는 유지 |
| 직접 검토 | 기존 속성 참조와 원본의 제안 경로 | 기존 경로와 원본 경로를 각각 보존 |

속성 참조는 해당 요청에만 유효합니다. 재시도·복구는 고정 입력의 목록을 사용하고, 새 문맥을 받으면 다시 생성합니다. 사용자에게 보이는 판단 설명에 속성 참조가 남는 경우의 기존 응답 검증·재시도는 유지하며, 해석 가능한 기존 대상·후보 참조의 이름 변환도 유지합니다. 이번 자연어 표현 정리는 이 참조 검증을 없애는 변경이 아닙니다. 설명 문장에 쓰인 `root`·`slot`·`snapshot` 같은 표현을 다듬기 위해 새로운 실패·유료 재시도 조건을 추가하지 않습니다.

이 계약은 잘못된 위치 형식을 줄이는 조치입니다. 의미가 다른 실제 속성을 AI가 잘못 선택하는 문제까지 해결했다고 간주하지 않습니다.

## 범위가 없는 후보의 직접 검토

예를 들어 원본의 범위 없는 `조명 지속 시간`과 기존 `불의 정령 → 지속 시간`을 비교하려는 경우, 이름이 다르다는 이유만으로 직접 검토 결과까지 실패시키지 않습니다.

다음 조건을 모두 충족할 때 명시적인 범위 확인 결과를 허용합니다.

- 원본 후보가 하나이며 원본 범위가 비어 있습니다.
- 선택한 기존 속성의 범위가 실제로 존재합니다.
- 원본 이름·범위·값을 제안 쪽에 보존합니다.
- 자동 수정·병합 대신 `REVIEW_REQUIRED / SCOPE_UNRESOLVED`로 보냅니다.

같은 이름의 여러 원본이 기존 scoped 속성과 모호하게 겹쳐 함께 검토되는 기존 동작은 유지합니다. 서로 다른 명시적 범위는 `SCOPE_MISMATCH`, 주체 연결 자체가 불명확한 경우는 `SUBJECT_UNRESOLVED`로 구분합니다. 이 상태들은 정상적인 보류 판단이며 실행 실패가 아닙니다.

## 묶음 내부 복구의 경계

### 묶는 기준과 독립성

처음에는 원본 범위·속성명이 같은 후보들을 함께 다시 비교합니다. 같은 원본 경로의 여러 근거를 임의로 나누지 않습니다. 모든 복구 요청은 동일한 기존 설정 목록을 봅니다.

복구 결과가 같은 기존 속성을 읽거나 수정하거나, 같은 위치에 값을 쓰거나, 상위 범위와 하위 속성 구조를 공유하면 서로 영향을 줄 수 있습니다. 그런 묶음은 다시 합쳐 함께 비교합니다. 한쪽 결과를 먼저 확정하거나 먼저 나온 결과를 승자로 선택하지 않습니다. 마지막으로 성공 결과 전체의 후보 포함 여부와 경로 충돌을 재검증합니다.

복구 중 추가는 원본 범위·속성명을 그대로 사용하며 기존 루트 속성 이동을 금지합니다. 따라서 다른 복구 묶음이 새로 만들 범위나 아직 저장하지 않은 속성에 의존해 결과를 만들지 않습니다. 수정·병합은 선택한 실제 기존 속성의 경로를 사용합니다.

예: 다섯 후보 중 네 후보가 독립적으로 유효하고 한 후보만 계속 실패하면 네 후보를 보존합니다. 두 후보가 같은 기존 속성을 바꾸려다 함께 실패하면 그 둘을 함께 남기고, 나머지 독립적인 후보만 보존합니다.

### 호출량과 중단 조건

- 일반 응답 시도는 설정된 횟수이며 로컬 기본값은 3회입니다.
- 실패한 다중 후보 묶음에 한해 추가 복구 호출을 최대 20회로 제한합니다. 저장 시 문맥이 바뀌어 처음부터 재비교하더라도 남은 복구 예산을 공유하며 20회로 초기화하지 않습니다.
- 복구 요청 자체는 응답 시도 1회입니다. 의존 관계 때문에 합쳐 다시 비교하는 호출도 20회에 포함합니다.
- 전체 진단 시도 번호는 30 이내입니다. 상한에 걸린 충돌 묶음은 임의로 적용하지 않고 실패로 남깁니다.
- 입력·문맥 변경, 토큰 부족, 작업 소유권 상실, Spring API 오류, 예상 밖 실행 오류는 일부 성공으로 완료하지 않습니다. 기존 작업 오류 처리를 따릅니다.
- 새 복구를 시작하는 조건은 응답 파싱·응답 검증·출력 절단입니다. 네트워크 장애에 대해 무조건 후보 수만큼 다시 호출하지 않습니다.

복구는 오류가 있는 묶음의 비용과 지연을 늘릴 수 있습니다. 정상 응답의 호출 수는 늘리지 않습니다. 이 상한은 작업 전체나 여러 워커의 합산 호출 수가 아니라 묶음당 상한입니다.

## API와 저장

완료 요청은 기존 결정 목록에 선택적인 `failures`와 `diagnostics`를 추가합니다. 실패 목록은 원본 후보 참조, 분류된 오류 코드, 고정 안내 문구와 안전한 진단만 담습니다. 성공 결정과 실패 목록의 합집합은 원본 후보 전체와 같아야 하며 중복은 허용하지 않습니다.

Java는 고정 문맥·대상·속성·후보 포함 여부·경로 충돌을 검증한 후 모두 저장하거나 모두 거절합니다. 재전송 시 같은 완료 내용은 멱등하게 처리합니다. 실패 후보는 `FAILED / PENDING_REVIEW`로 남고, 정상 후보의 자동 확정을 방해하지 않습니다. 모든 후보가 실패해도 실패 목록 전체를 기록하고 자동 분석의 다음 묶음·회차 진행 정책을 따릅니다.

V51은 세계관 후보에 `comparison_diagnostics` JSONB 열을 추가합니다. 기존 후보의 진단은 NULL이며 API에서는 빈 목록으로 제공하고 기존 분석·확정 결과를 수정하지 않습니다.

진단에는 다음만 저장합니다.

- 어느 시도에서 어떤 검증 규칙에 걸렸는지
- 입력에서 확인되는 원본 후보 참조
- 실제로 선택했고 입력 목록에 존재하는 대상·범위·속성

선택 가능한 속성의 추천 목록을 실제 선택으로 기록하지 않습니다. 알 수 없는 참조, 원문, 속성값, 프롬프트, 원시 응답 및 자유 형식 예외 문자열은 새 진단에 포함하지 않습니다. 후보당 최근 진단 최대 30개를 보존합니다. 실제 대상 식별자는 API에서 `targetWorldSettingId`로 전달합니다.

## 화면에서의 차이

- 주체 연결을 보류한 결과는 **대상 연결 확인 필요**로 표시합니다.
- 범위 미정과 서로 다른 범위의 비교는 별도 안내를 표시합니다.
- 선택한 대상이 없으면 **비교 대상 미정**으로 표시합니다. 확인하지 못한 기존값을 없다고 단정하지 않습니다.
- 서버가 정한 보류·오류 안내를 AI의 판단 설명처럼 표시하지 않습니다.
- 실패 시 진단이 있으면 마지막 비교의 범위·속성을 보여주며 내부 식별자와 참조는 숨깁니다.
- 원본과 기존 속성 이름이 다른 검토도 양쪽 경로·값을 보존하며, 직접 저장 전에는 확정하지 않습니다.

## 자동 반영 보류와 비교 실패의 구분

V52는 자동 반영에서 확인한 보류 사유를 `automatic_review_hold_reason`에 별도로 보존합니다. 대상이 같은지,
현재 설정이 바뀌었는지, 저장 위치가 충돌하는지를 안내하기 위해 정상 비교를 실패로 바꾸거나 기존 AI의
추가·수정·병합 제안을 덮지 않습니다. 확정 시 실제 대상·기존값·범위/설정 전체 경로는 계속 재검증합니다.
명시적인 사용자 수정안만 대상과 반영 방식을 다시 선택할 수 있습니다.

기존 기록은 보류 사유가 없을 수 있습니다. 이를 추측해 채우거나 과거 실패 진단을 새로 만들지 않습니다.
공개 판단 문장의 개발 표현은 조회 시 자연어로 정리하지만, 원문·설정값·저장된 AI 결과는 바꾸지 않습니다.
세계관 목록도 반영·제외·직접 확인·비교 대기/진행을 묶음 전체에서 중복 없이 계산합니다.
원본 회차가 자동 분석·반영 중인 미확정 후보는 비교가 끝났어도 `automaticApplicationPending=true`로
진행 집계에 포함합니다. 이때 수정·확정·제외·재비교는 후속 분석 무효화 전에
`409 / ANALYSIS_AUTOMATIC_APPLICATION_PENDING`으로 거절합니다. 완료된 앞 회차 보류 항목은 기존대로
직접 확인할 수 있습니다. 정확한 조건과 잠금 경계는 [자동 분석 신뢰성 문서](automatic-review-reliability.md)를 따릅니다.

## 검증과 읽을 파일

아래 파일 경로는 AI 저장소 기준입니다. Java의 저장 계약은 [세계관 문서](world-setting.md)와 [순차 분석 문서](ordered-provisional-analysis.md)를 함께 참고합니다.

무료 고정 응답을 사용한 테스트로 형식 오류 및 복구의 동작을 검증합니다. 실제 소설 분석의 정답률·재현율 개선을 측정한 결과는 아닙니다.

- `app/analysis/ordered_world_batch_contract.py`: 요청용 선택 스키마와 비교 규칙
- `app/analysis/ordered_world_diagnostics.py`: 속성 선택 복원과 안전한 진단
- `app/analysis/world_setting_comparator.py`: 실제 LLM 호출·응답 검증
- `app/analysis/world_setting_batch_recovery.py`: 제한된 재비교와 의존 관계 처리
- `app/analysis/world_setting_pipeline.py`: 복구 호출·API 완료·실패 집계
- `app/schemas/worker.py`: Java와 주고받는 결과·진단 계약
- `tests/test_ordered_world_property_selection.py`, `tests/test_world_setting_batch_recovery.py`: 선택 계약·복구 경계
- `tests/ordered_analysis_http_harness.py`: 실제 Java HTTP와 PostgreSQL을 통과하는 무료 고정 응답 검증

## 대상이나 내용을 확정할 수 없는 정상 검토

범위 차이가 아닌 대상 연결·내용 해석의 불확실성은 `REVIEW_REQUIRED + GENERAL_UNCERTAINTY`로 저장한다. 예를 들어 원문의 ‘미궁’ 설명을 제공된 ‘백탑’ 정보와 같은 대상으로 보아도 되는지 결정하지 못했다면, 비교를 완료하고 해당 후보만 직접 검토 대상으로 남긴다. 다른 설정의 자동 반영과 다음 회차 분석은 이어진다.

- 단건 및 두 묶음 비교 방식에서 동일하게 지원한다. 묶음 응답도 출처 후보를 하나씩 보류하며, 서버에 전달하는 제안 경로·값은 원본과 동일해야 한다. Worker는 기존 단건 원본 복원 규칙을 적용한다.
- 기존 대상을 지정하면 실제 제공된 대상이어야 한다. 기존 속성 선택은 생략할 수 있으나 선택한 경우 전체 경로가 존재해야 한다. 범위만 지정하고 속성을 생략하거나, 속성을 이동하거나, 여러 출처를 하나의 검토 결정으로 합치면 거절한다.
- 확정 설정은 변경하지 않는다. 누적 참고 기록과 다음 회차 참고는 원본 주체·값·근거를 유지하고 `UNCONFIRMED`로 구분한다. 판단을 위해 선택했던 대상은 확정된 동일 인물·동일 세계관 대상이라는 뜻이 아니다.
- 사용자는 기존 결정 수정과 확정 화면으로 대상·경로·값·반영 방식을 직접 선택할 수 있다. 새 LLM 호출 없이 확정하며 비교 당시 검토 사유는 보존한다.
- 범위 미상과 범위 불일치 사유의 검증은 그대로 유지한다. 이번 변경은 답변 형식 오류를 무조건 허용하는 처리가 아니며, 기존 `FAILED` 결과를 자동 수정하지 않는다.

DB 변경은 `V54__allow_general_world_uncertainty_review.sql`만 추가한다. 기존 migration과 사용자 후보 데이터는 변경하지 않는다.

검증: 2026-09-11 Java 전체 회귀는 1,020개 통과, 환경 조건 등으로 35개 생략되었고 실행 JAR 빌드가 완료됐다. 별도 PostgreSQL에서 V52까지 적용한 실제 Python↔HTTP 2회차 검증도 통과했다. 첫 회차에서 일반 검토는 원본 ‘미궁/구조’로 남고, 정상 ‘백탑/색상’은 자동 반영됐다. 다음 회차는 확정 색상과 원본 미확정 참고를 읽어 완료했다. 이 검증의 모델 응답은 고정 대역이며 외부 LLM 호출은 없으므로 모델의 실답변 정확도 측정 결과로 해석하지 않는다.
