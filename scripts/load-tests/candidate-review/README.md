## Timing

Coordinate a quiet window with the parent agent: no Gradle, FE builds, tests, SQL debug, other benchmark, or browser traffic during API timing.

`measure.py --root <root> --phase before|after --jar <preserved-actual.jar>` runs character pending list, world pending list, and old unfiltered world size1 / new summary. Each route gets a fresh JVM,3 sequential warmups, then30 sequential measured requests. Requests are identical except the intended size1→summary replacement. Timeout is45s. Any non200, network failure, validation error, or OOM stops that series immediately; missing samples remain missing. It will not overwrite completed evidence. The owned Java process is stopped after each route, including failures.

The runner stores every sample, complete first successful `data`, median, nearest-rank p95, error count, response bytes, actual JAR/fixture/script hashes, Java/PG/host limits, GC logs, and0.5s RSS/jstat samples. RSS peaks are observed samples; GC collector time is not pause time. OS/DB caches are not reset. Heap, native-process RSS and PostgreSQL repeated JSON text are different quantities.
